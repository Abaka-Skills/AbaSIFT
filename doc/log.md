# Decision log

**Historical record, not the contract.** [design.md](design.md) is normative: it states what
the framework guarantees today and why. This file records how it got there — the questions
in the order they came up, so a decision that was later revisited (#26 by #40 and #42;
#21 by #46 and #48; #38 by #50) reads as a sequence rather than something silently
rewritten.

Nothing here is authoritative. Where an entry and `design.md` disagree, `design.md` is
current and the entry is what was true at the time. Entries are never edited after the fact
and never renumbered — two entries share the number 37, settled the same day and
distinguished as 37a / 37b, because the numbers were referenced from code and other docs
while the log was live.

The package was named `abasift` partway through implementation — see #15.

## Decisions taken before implementation

The first fourteen were settled before any code was written, and are recorded as
decision-versus-alternative.

| # | Decision | Alternatives rejected |
|---|----------|----------------------|
| 1 | Scope 1: framework + demo pipeline | Building orchestration or full platform |
| 2 | Job = YAML config (loader over S3 dirs); atom flowing through DAG = **sample** | Job-per-file (kills cross-modality checks), time-window atoms |
| 3 | Batch = efficiency unit; outputs per-sample | Batch as semantic unit |
| 4 | Fully **lazy** loading via `LazyRaw` (uri + decoder) | Staged-download hybrid; eager materialization |
| 5 | Two-tier cache: disk (raw, worker-global LRU) + in-memory decode memo (per batch run) | No cache; memory-only |
| 6 | Parallelism **within** the DAG: concurrent independent branches, threads | Sequential topo walk + many samples in flight (multiplies decoded memory) |
| 7 | **Threads only**; no proc/cmd node runtimes | Per-node proc/bash escalation (serialization tax; deferred) |
| 8 | ArtifactUnion: flat node-namespaced map, **extend-only**, executor-owned union at joins | Nested trees; kernel-side merging; overwrite rights |
| 9 | Loader = **node 0** (SourceKernel); batch travels inside the ArtifactUnion | Separate job YAML for loader; special batch parameter |
| 10 | `DataArchiver` = the one sanctioned mutator: dump→LazyRaw swap, empty target→delete, deterministic paths | Letting any kernel mutate; timestamped dump paths |
| 11 | **Per-batch streaming through the DAG + terminal `digest()`** | Stage-wise (all-batches-then-propagate): chosen at first for report-merge fears, rolled back once per-sample keys proved disjoint across batches (dumb union); streaming restores decode sharing and bounded memory |
| 12 | Report: minimal enforced skeleton; kernel verdicts, YAML thresholds; `error` first-class | Free-form reports; heavyweight per-check schemas |
| 13 | Distribution is **external** (per-machine YAMLs generated by an outside system) | In-framework sharding + merge tool; central batch queue |
| 14 | fsspec for all I/O; AWS credential chain; kernel resolution by dotted import path | boto3-only; credential params in YAML; string registry |

## Decisions taken during implementation

Everything from #15 on was settled *while* implementing, and each one carries its reasoning
in full — those are the entries that answer "why is this like this" when the code alone does
not.

### #15 · Package and CLI named `abasift`; the loader is `FlatDirLoader`

`LocalDirLoader` would have lied: the same class serves an `s3://` prefix unchanged, which is
the whole point of going through fsspec.

### #16 · `LazyRaw` exposes three access modes, and the decoder picks

`open()` reads ranges remotely, `local_path()` materialises into the disk cache, `read_bytes()`
loads whole and refuses oversize payloads. One mode cannot serve both ends: on a 177.9 MB DJI
MP4 a container-header probe reads 0.45 MB, while demuxing the interleaved telemetry track
over the network reads 177.90 MB in 4406 ranged GETs.

### #17 · `ReportExt` is a typed object (`checks` + `summary`) instead of a bare dict

`run()` and `digest()` both return report fragments. A bare dict lets a kernel write into the
enforced skeleton by accident; a typed object gives both one return type and no way in.

### #18 · `Batch`-valued keys are dropped when merging a batch union into the job union

Union values are meant to be primitives or `LazyRaw`. `load/batch` would otherwise arrive with
a different value every batch and trip the conflict check — and would pin that batch's decoded
payloads for the rest of the job.

### #19 · A node's view = the union and report of its *ancestors*, not global state

Kernels skip samples that already failed upstream. Against a shared, concurrently updated
report, whether branch B skipped a sample branch A had just failed would depend on thread
scheduling, and two runs of one job could disagree. Ancestor-scoped views make the report
scheduling-invariant.

### #20 · Kernel params are strict (explicit signatures, no `**kwargs`)

The alternative is a catch-all that swallows typos. For a QC framework a mistyped threshold
silently defaulting is worse than a crash, so a bad param is a load-time `PipelineError`.

### #21 · Mutation is a separate interface, not a convention

Either any kernel may rewrite an artifact by agreement, or the right is carried by a type.
In-place mutation of a union that concurrent branches share is unsafe, and "who may rewrite"
should be answerable by `isinstance`. Deletions are recorded in the union so a join with a
branch that never saw them cannot resurrect the key.

### #22 · The terminal pass is two-phase: all reduces, then job stats, then the writes

An archived `report.json` has to contain the job block — counts, elapsed — which is only known
once every `digest()` has run. So writing happens in a second pass, after the stamp.

### #23 · The `SampleKernel` base class owns the per-sample failsafe

Every check kernel needs drop-on-upstream-error and exception→`error`. In the base class it is
implemented once, and a node contributes exactly one check key per sample whether its kernel
succeeded or not.

### #24 · The stream registry is reduced to a validated `kind/name` prefix set

The agreed design had every stream kind declaring required fields (e.g. a common time base,
for sync kernels). Only the prefix check is implemented: it catches the mistake actually seen
in practice — a loader inventing `telemetry/main` — while declared per-kind fields pay off
only once a sync kernel exists to consume them. **This is the one place the implementation
under-delivers against the agreed design** — flagged, not hidden.

### #25 · `art.batch()` finds the `Batch` by type, not by a configured key name

The alternative makes every kernel hardcode the name the YAML gave the loader. Finding by type
raises on missing or ambiguous rather than silently reading the wrong thing.

### #26 · A concrete dump layout: `{target}/{job_id}/{node}/{name}`

The design said only `f(job_id, node, key)`. A job-scoped directory keeps one run's outputs
together and makes a cross-job overwrite impossible. Revised later by #40 and #42.

### #27 · CLI exit codes: 0 = the job reported, 2 = the YAML is broken

QC failures are data findings, not process failures. An orchestrator must not retry a job
because a vendor's video was corrupt, so any set of verdicts still exits 0.

### #28 · Loaders take `max_samples` / `order` (`name` | `size`) / `batch_size`

Cheap probes and cheap tests over a huge delivery. Explicitly **not** sharding — distribution
stays external (#13).

### #29 · `EgoverseDjiLoader` declares `imu/main` for every sample, telemetry or not

Knowing which files carry telemetry would mean opening every object at enumeration time.
"Declared but unreadable" already has a right answer (`MissingStream` → `error`), and *which*
files lack IMU is a QC result, not a loader precondition.

### #30 · The reverse-engineered DJI field mapping is guarded by physics

The mapping is inferred, not specified. Guards (`‖q‖≈1`, median `‖a‖∈[0.5,2] g`, monotonic
timestamps) and rejection of unrecognised layouts mean a firmware change that moved the fields
fails loudly instead of reporting plausible-looking nonsense.

### #31 · Spike statistics: median/MAD, a scale floor, and an honest 2-per-impulse count

Mean/std hides what it is meant to find — a handful of large spikes inflates σ enough to
conceal themselves. First differencing makes one impulse perturb two consecutive differences,
so it counts as 2; documented rather than smoothed away, so the measurement stays explainable.
A track shorter than `min_samples` is `error`, not `pass`: unmeasurable is not clean.

### #32 · Executor scheduling is a driver loop, not level barriers

Level barriers waste wall-clock on uneven branches; pool tasks that block waiting on
dependencies can starve the pool. Submit-ready → wait `FIRST_COMPLETED` → fold has neither
failure mode.

### #33 · Flat package layout, with `pyflakes` as a tracked dev dependency

Requested. The linter is tracked so "imports are clean" is checkable rather than asserted.

### #34 · An omitted `target` means a relative, per-run tree; an explicit one is verbatim

Two needs pull apart. A YAML an external splitter generates must be idempotent on retry, so an
explicit `target` is used verbatim and unstamped — hard rule #10 intact. An interactive run
must not collide with its own earlier output, so an omitted `target` gets a dated subtree, paid
for in directories that accumulate until someone clears them. The stamp is read once from the
job start time so every writer in a DAG agrees. Free mode needs an explicit `""`, so the
destructive branch is never the default.

### #35 · Two hosted views, never a generated file

Requested. A generated page is a snapshot that is wrong the moment the YAML changes, with
nothing to say so; hosting re-reads the YAML and re-imports edited kernels on every request.
The boxes are derived by `inspect`ing the classes the YAML names rather than transcribed, so a
renamed parameter changes the picture or the YAML visibly fails to load. Hot reload is scoped
to the kernels a YAML names — never the core contracts, since a second `Kernel` class would
break every `issubclass` check in the validator.

### #36 · The executor takes an optional `observer(event, **payload)` and emits six events

The live view needs progress the report cannot give it: the report only exists once the job
ends. A callback keeps the dependency pointing the right way — the executor imports nothing
from `vis` and does not know anything is watching — and `_emit` swallows whatever an observer
raises, because telemetry must never be load-bearing.

### #37a · `SampleKernel`'s per-sample hook is named `sift`, not `check`

The hook decodes, measures, derives artifacts and *then* judges; `check` described half of it.
What it returns really is a judgement, and `samples.<id>.checks.<node/check>` is a consumed
contract, so the rename stops at the method.

### #37b · `pipeline.cache: {dir, size_gb}` configures the worker scratch disk

The cache is where a job's money goes (a 2 GB video materialised per sample), and the splitter
knows the machine while the environment does not always. YAML wins per setting, so `size_gb`
alone still honours `ABASIFT_CACHE_DIR`. Silence must install *nothing*: the cache is
process-global, and overwriting it would trample one a test fixture or an embedding program
installed on purpose. Applied in `__init__`, before any kernel can read a byte.

### #38 · `abasift run` opens with a banner: resolved infrastructure, then the DAG

A worker log should answer "where is this writing, how much disk may it eat, what is it about
to run" without anyone opening the YAML. It is read off the objects the job will actually use,
so it cannot promise one thing and do another. Edges are **named, not drawn**: there is no
honest ASCII layout for an arbitrary DAG, while dependency order plus explicit inputs prints
any shape. (Revised by #50: the names stay, but the edges are now *also* drawn — routing on a
fixed row order turns out to be exact, which was the objection.)

### #39 · Colour only on a TTY, never under `NO_COLOR`, never on the message

These logs are grepped by a fleet as often as they are read by a person, and escape codes in
one are worse than no colour at all. Levels are padded *before* painting — otherwise the escape
bytes count toward the width and knock every coloured line out of its column.

### #40 · The dump directory is `{job_id}_{pipeline_hash}`, not `{job_id}` alone

A retried shard reuses its id by design, so `f(job_id, …)` overwrites idempotently. But an
*edited* YAML retried under that id would overwrite artifacts produced by different thresholds,
destroying the evidence behind a verdict someone has already read. The hash separates "same job
again" from "different job, same name" with no timestamp involved.

### #41 · The job emits two documents: `report.json` per sample, `pipeline.json` per node

Requested. Thresholds and params are identical for every sample a node judged, so repeating
them per sample is most of the file on a 100k-sample delivery. Splitting by what a fact is
*about* gives each document one job, and both carry the same `job` block so either reads alone.
The price is that neither contains the exact blob the hash covers — acceptable, because the
verbatim YAML sits at the job root and `job.pipeline_hash` is in both.

### #42 · The default layout puts the timestamp *inside* the job directory

The first version had it outermost, which scattered one shard's runs across sibling trees — a
job's history could not be listed without globbing. Job first also gives the config copy a home
(`{job_root}/pipeline.yaml`) that no single run owns.

### #43 · `pipeline.name` is removed; `job_id` is the one name a job has

Nothing was keyed on `name`: dump paths use `job_id`, and the definition is identified by its
hash. Two free-text labels for one thing drift — the shipped YAMLs already disagreed. Strict
`pipeline:` keys mean an old YAML fails at load instead of running with a surprise `job_id`.

### #44 · A shared frame-decode *node* (`VideoFrameKernel`), not a decoder, not per-kernel

Four pixel-level checks over one video would otherwise decode it four times, and every check
author would re-derive "frames at 1 fps". A **node** rather than a decoder, because the
sampling policy belongs in the YAML beside the thresholds and the result is then an artifact
the DAG can archive, free or reuse. A **handle** rather than an ndarray, because the job union
accumulates every batch and `without_transients()` drops only the `Batch` — an array parked
there would live for the whole job. The cost moves to disk and is real: raw rgb24 at 1 fps is
larger than the compressed source (159 MB of clips → 381 MB of frames), so it is bounded by
`pipeline.cache.size_gb` and reported as `cache_bytes`. The cache key is `f(source, fps, size)`,
the same determinism rule as dump paths.

### #45 · `VideoDumper` writes a frame stack back out as a video, `fps` = playback rate

A verdict a vendor will dispute is worth an exhibit beside the report that explains it.
Playback rate has to be separate from sampling rate because both readings are legitimate: a
1 fps stack at 1 fps is a real-time proxy, the same stack at 25 fps is a timelapse. The rate is
a `Fraction`, so 29.97 stays 30000/1001. It remains a `SampleKernel` — it adds an artifact and
rewrites nothing — and it finds its input stack by *decoder*, following #25.

### #46 · The per-batch merge folds only the *leaf* nodes' unions and reports

Every node's union already contains its ancestors', so folding the whole graph back in was
redundant — and wrong once a `MutatingKernel` *replaced* a value: the ancestor still holds the
pre-mutation copy, so one key arrived with two values and the merge refused to pick a winner.
It fired on a **linear** three-node DAG, which is why "forbid mutation on branches" was never
the fix. Sibling leaves can still disagree, which is what the sticky `deleted` set settles. The
report follows the same rule for symmetry: merging it is additive, so the redundancy could
never disagree the way the union can, but one rule for both beats a harmless special case.

### #47 · Writers split by what they do to the union: *archiver* vs *dumper*

Both were called "dumper" while doing categorically different things to the job's state, and
the dangerous one sounded routine. Archive = write the value out and take the object out of the
working set; dump = write something out and leave the union as found. Naming it makes the rule
self-evident at the call site: an archiver is a `MutatingKernel` and there is exactly one, a
dumper is an ordinary `SampleKernel` and there can be many. What they genuinely share — where a
write lands — stays in `_dump.py`. The output directory keeps the name `dump/`: it is a place
both write to, not a claim about the union.

### #48 · Two nodes replacing one key on parallel branches is rejected at load

One key with two values has no honest winner, so unlike a stale ancestor (#46) no merge rule
could settle it — the only question is when the author finds out. Load time, because the
mistake is visible in the YAML, and mid-job is after both files have already been written. The
validator asks each mutating kernel for its patterns rather than knowing what a `DataArchiver`
is, and glob overlap is tested conservatively: general glob intersection is not decidable by
inspection, and a validator that guessed would be worse than one that states what it checked.

### #49 · The terminal hooks are renamed for what they do: `digest()` and `commit()`

`finalize` named *when* they run — which the executor decides — and gave one name to two
different passes: one reduces per-sample facts into summaries and touches nothing, the other
writes the finished job out after its counts are stamped. Neither *merges* the batches; the
executor has already done that by the time `digest()` is called.

### #50 · The banner draws the DAG's edges as rails, *and* keeps naming them

#38 refused to draw edges because there is no honest ASCII layout for an arbitrary DAG. That is
true of *layout* — placing nodes to minimise crossings — but not of *routing*: with the nodes
already fixed one per row in dependency order, the columns are a lane allocation, which is
exact. A lane lives from a node's row to its last child's row and is then reused, so the gutter
is as wide as the edges in flight rather than the pipeline; a link row between each pair of node
rows is where an edge turns out of its lane. The `← inputs` labels stay: the rails give the
shape at a glance, the names survive a gutter too wide to trace by eye, and both are generated
from the same `inputs` in one pass, so there is no second copy to keep in step.
