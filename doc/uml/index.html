AbaSift — architecture diagrams

Distributed QC framework for egocentric vendor datasets. A job is one pipeline YAML run on one machine; work distribution is external. These are the six views that matter for review — this page is the only copy of them. The contract and its reasoning are in doc/design.md.

1Module layers — imports point one way

Kernels and loaders depend on the core contracts and on nothing else — never on the executor, never on each other. Vendor format knowledge is a leaf, reached only through a registered decoder, so adding a vendor touches loaders/ + vendor/ and stops there.

The one upward-looking edge is decoders.py → vendor/: the registry imports the DJI reader so a LazyRaw can name "dji_imu" as a plain string. That keeps vendor code out of every other module, at the price of one import the layering would otherwise forbid. vis/ is dashed because it hangs off the side of the stack: it imports pipeline.py and, through it, the kernel classes a YAML names — only to inspect them. Nothing in the data plane imports it, and it does no I/O. Under run --vis the executor pushes progress back to it through a plain observer(event, …) callback, so even then the executor stays unaware of who is watching.

2Data plane — what flows through the DAG

LazyRaw is uri + decoder name + opts: serializable, cheap to enumerate by the million, and nothing is fetched until a kernel asks. Everything downstream of it is a decoded payload type that check kernels can be written against without knowing the vendor.

ArtifactUnion holds the Batch under the source node's namespace (load/batch) — one uniform kernel signature, no special-cased batch parameter. It is dropped when a batch's union is merged into the job union: it is a live object and would otherwise collide across batches on the same key.

3Control plane — kernels, pipeline, report

Four kernel classes, three of which a QC author might subclass. Inputs are read-only; kernels return only extensions and the executor namespaces and merges them.

4Execution flow — per-batch streaming + terminal digest

One batch at a time through the whole DAG, branches in parallel, then a dumb per-sample merge (keys are disjoint across batches), then the decoded payloads die. Memory is bounded by batch size, not dataset size.

A node's inputs are the union and report of its ancestors, never global "whatever finished first" state. Since kernels skip samples already marked error, a shared report would make the outcome depend on thread scheduling; ancestor-scoped views make the report scheduling-invariant.

5Access modes — where the money is spent

Vendor videos run 70 MB–2 GB. The decoder picks the access mode, and picking right is the difference between half a megabyte and two gigabytes. Numbers measured on one 177.9 MB DJI MP4.

6Failsafe layers — the job always completes

error is a first-class status: unreadable data is itself a quality defect. Nothing propagates out of Executor.run().
